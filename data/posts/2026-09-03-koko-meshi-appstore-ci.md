summary: 手元に Xcode が無いので、署名・書き出し・アップロードをすべて CI に載せた
projects: [koko-meshi]
---

手元は Windows で Xcode を持っていない。iOS 版を App Store に出すには、署名も書き出しもアップロードも CI でやるしかないので、その流れを組んだ。

![App Store への提出を CI だけで通す](/devlog/2026-09-03-koko-meshi-appstore-ci/submit-pipeline.svg)

| 決めたこと | 理由 |
|---|---|
| macOS のランナーの版を固定する | 提出には iOS 26 SDK が要る。latest 指定だと、世代交代で黙って古い SDK になりうる |
| アーカイブの前に、署名なしのビルドを必ず走らせる | ここでプラグインの統合が行われる。飛ばすとアーカイブが落ちる |
| 署名設定は設定ファイルに追記する | コマンドの引数で渡すと全ターゲットに効き、パッケージのリソースバンドルで失敗する |
| 地図のキーが無いときだけはビルドを落とす | 地図の出ないアプリを提出しても通らない |

署名まわりの秘密情報が未登録のうちは、各ステップが飛ぶだけで失敗しない。

Bundle ID も直した。Flutter が作った既定値のままで大文字も混じっていたが、提出後は変えられない。Android の ID はすでに配布しているので変えていない。アーカイブは、配布用のプロファイルに含められないデバッグ専用のメモリ権限を要求して落ちていたので、それを外した。端末内 AI のメモリ上限を上げる 2 つの権限は残している。
