summary: 重複の原因を 1 つずつ潰し、最後にハイライトの仕組みごと作り直した
projects: [omniverse]
---

通知の同じ項目が二重三重に出ていた。鍵アカウントなど通知の多いアカウントで目立つ。1 日で 7 回直した。

| 原因 | 直し方 |
|---|---|
| REST と GraphQL で同じ通知の ID が違う | 対象の投稿 ID で突き合わせ、REST を優先して統合 |
| 追加読み込みと初回ロードに重複チェックが無い | 既存の ID を見てから足す |
| X が同じ投稿へのいいね/RT を、人数が変わるたび別 ID で返す | 種類 + 対象の投稿 ID を「同じ出来事」のキーにした |
| 同じ出来事が更新されても古い位置のまま | 新しいデータで上書きし、時刻順に並べ直す。本家と同じく先頭へ移る |

新着のハイライトは「既読ライン」と「光った ID の記録」の二重管理で、タブを行き来すると光らなくなっていた。通知ごとの最終閲覧時刻(seenAt)に一本化し、更新された通知はもう一度光るようにした。

429 のときはリトライしないようにもした。この日は iOS の Google ログインも、Android と同じポップアップ方式に戻している。
