フォロー/フォロワー取得の DB(949 行)とジョブ制御(430 行)は、一度もテストされていなかった。本番と同じスキーマとマイグレーションを実際に走らせるテストを書いたところ、不具合が出てきた。

![Bluesky 対応は取得口の差し替え](/devlog/2026-08-23-omniverse-follow-bluesky/fetcher-swap.svg)

| 見つかった不具合 | 中身 |
|---|---|
| 連続実行の途中で WebView を畳んでいた | 畳む条件の変数が常に null。2 本目が破棄済みの WebView に投げて失敗し、30 秒の再試行に載っていた |
| 走査が running のまま残る | WebView の待機が try の外にあり、タイムアウトで後始末を通らなかった |
| 対象が二重に見える | handle を引くときだけ小文字化し、書くときは素通しだった |
| 同じミリ秒のスナップショットの順序が不定 | 並び順の第 2 キーに id を足した |

そのうえで Bluesky に対応した。Bluesky は公開の API を素の HTTP で呼べるので、取得口を差し替えるだけで済む。一覧にはフォロワー数などが入らないため、25 人ずつプロフィールを引き直して補う。
